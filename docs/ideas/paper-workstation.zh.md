# Paper Workstation

论文阅读工作台，支持找论文与读论文。优先从实际阅读中积累经验，再改进搜索与
阅读方式。MVP 专注论文搜索、术语查询、PDF 阅读，以及产出便于回看的笔记。

## MVP 范围

- 论文搜索来源限定为 arXiv。
- 阅读已有 PDF，并围绕用户的问题解释论文内容。
- 英文 Wikipedia 作为概念理解的辅助来源，不要求每个术语都查询。
- 根据讨论整理笔记，保留问题、相关术语与解释，方便后续回看。
- 单一 repo 使用的 extension，不考虑多 repo 与 extension 隔离策略。

找论文与读论文都在范围内，阅读优先推进，不意味着排除搜索路线。

## 阅读与交流

优先解释用户当前的问题，确有理解障碍时再展开前置概念，避免大量铺垫分散
注意力。不把术语查询或固定章节顺序作为每次阅读的必经步骤。

先积累实际使用经验，跑通机械流程，再考虑编写快速阅览论文的 skill 或调整
其他 agent config。

笔记以便于用户阅读、恢复理解为目标，不预设统一模板。Apalache 阅读笔记是
目前有效的参照，但尚未明确其中哪些特点值得固化。

MVP 默认便于用户阅读的笔记也可作为 agent 后续理解的基础，不额外设计面向
agent 的表示或校验机制。

## 材料保存

PDF 与查询取得的 Wikipedia wikitext 全部保留，避免现阶段将注意力投入筛选、
缓存与索引策略。

两类材料的用途不同：

- 高价值 PDF 值得反复阅读，是长期保留的原始材料。
- Wikitext 主要用于减少重复请求，不是术语理解的最终产物。
- 对论文与术语的理解整理到笔记中，作为后续回看的主要入口。

暂不设计索引、缓存淘汰与更新策略，也不处理同一概念在不同语境中的理解管理。
先快速使用，遇到实际问题后再决定如何扩展。

## 现有尝试与工具去留

已经尝试：

- 使用 PDF.js 编写 `pdf_read` 和 `pdf_grep`。
- 使用 Wikipedia API 编写 Pi extension。
- 使用 arXiv API 编写 Pi extension。

自制 PDF.js 工具使用中频繁出现字体问题，且实现对使用者而言是黑盒。当前
重点不是解析 PDF，因此决定复用现成 PDF skill 替换，不继续追查或改进这些
问题。候选为 Claude 或 OpenAI 官方使用的 PDF skill，具体选择尚未确定。

暂时保留现有 Wikipedia extension，不重做。Wikipedia 是目前顺手的高价值
信息来源，后续根据阅读体验决定保留、调整或替换。

持久化需求本身不作为迁移到 MCP 的理由，当前不因此重构接入方式。

## 暂不处理

- 论文复现。
- 并行任务。
- OCR。
- 索引与独立术语库。
- 多 repo、共享存储与 extension 隔离策略。
- 判断用户是否已经理解，以及何时宣布学习完成。
- 提前固化阅读交流 skill 或其他 agent config。
