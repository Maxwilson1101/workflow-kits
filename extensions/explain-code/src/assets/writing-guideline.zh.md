# 中文代码讲解写作指南

本指南约束讲解文字的用词、结构和风格，供撰写与完成后的语言检查使用。

## 语言风格

### 直接客观

直接陈述事实，使用平实、自然的语气。省去“我们可以看到”“这里需要注意”等引导语，
避免反问、感叹、夸张评价和拟人化表达。

示例：

- 原句：我们可以看到，这里需要注意，取消后任务仍可能继续执行。
- 修改后：取消后，任务仍可能继续执行。

### 简洁准确

明确动作主体，优先使用主动表达。删去不影响含义的字词，少用“进行一个检查”“实现了
对……的处理”等冗长结构。精简时保留条件、否定和可能性等影响准确性的限定。

示例：

- 原句：在请求发起之前，会进行一个取消状态的检查。
- 修改后：函数在发起请求前检查取消状态。

### 用词一致

使用通行的中文技术术语，同一概念保持同一种称呼，避免交替使用不同译法或中英文
名称。保留 API 名称和代码标识符的原始拼写与大小写，不自创缩写或生硬译名。

## 文档结构

### 标题

标题使用简洁的中文名词短语，含义明确。同级标题保持相近的结构，不以句号或问号
结尾。标题层级连续，不跳级，不重复上级标题。

示例：

- 原句：关于取消信号是如何被处理的说明
- 修改后：取消信号处理

### 段落

每段围绕一个主题，核心句放在段首，后续句子补充条件、原因或结果。主题变化时
另起一段，避免在多个段落中重复同一意思。段落可以只有一句话，不设固定字数下限。

### 句子

一句话表达一个主要意思。明确条件、动作与结果的关系，避免多层嵌套和“一逗到底”。
长句按逻辑断开；代词指向不清时，直接写出所指对象。

示例：

- 原句：如果任务返回时等待已经取消，就会把结果交给回调，然后退出，
  这样调用方就能释放资源，而不会再次完成外层 Promise。
- 修改后：如果任务返回时等待已经取消，函数会将结果交给回调后退出。
  调用方可以在回调中释放资源，外层 Promise 不会再次完成。

## 文字格式

- 中文句子使用中文标点。英文名称、代码表达式内部的符号保持原样。
- 中文与英文、数字之间留一个半角空格，中文标点两侧不额外加空格。
